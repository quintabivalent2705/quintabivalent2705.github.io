# Wang Xiaopei · Academic Homepage

王潇霈的中、英、越三语学术主页，使用 Vue 3 与 Vite 构建，通过 GitHub Pages 发布：

- 网站：[https://xiaopei388.github.io](https://xiaopei388.github.io)
- 仓库：[xiaopei388/xiaopei388.github.io](https://github.com/xiaopei388/xiaopei388.github.io)

本仓库是公开仓库。README、网站源代码、公开内容数据、提交记录和 GitHub Actions 日志均可能被外部查看。仓库只保存网页实际显示且已经确认可公开的字段；完整资料和 AI 维护手册保存在用户的私人 Notion 主库中。

## AI 接手时先做什么

1. 先读取私人 Notion 主库中的“AI 维护手册｜学术主页”和相关数据库，再读取本 README。
2. 检查工作区状态，保留用户已有但尚未提交的修改。
3. 以当前文件为准，不从旧截图、旧导出文件或 Git 历史恢复已经删除的内容。
4. 只把用户明确确认可公开且页面实际使用的字段同步到本仓库；其余内容继续留在 Notion。
5. 完成修改后运行 `npm run build`，再检查中文、英文、越南语、桌面端和移动端页面。
6. 验证通过后提交到 `main`，等待 GitHub Pages 工作流完成，并检查公网页面。

## 公开内容规则

- 项目 `id` 必须唯一并保持稳定。
- 项目、成果和研究方向之间的关联名称必须与中文主数据完全一致。
- 中文正式成果题名保留公开出处中的原始名称；英文和越南语模式可采用适合相应读者的自然学术表达，但内部关联仍使用中文主键。
- 新增或删除项目、成果时，同步检查首页代表性内容、相关方向、相关项目以及英文和越南语翻译。
- 页面只展示已经发生并经用户确认可公开的内容；在投、在审或申请中成果也必须先在 Notion 中取得明确公开状态。
- 每个公开字段必须被当前页面实际使用。访问记录、内部项目规模、企业案例数量和备用字段不得作为隐藏数据留在仓库。
- 三种语言页面都要检查备注式、自证式、防御式和模板化 AI 表达。

## 本地检查与发布

首次运行：

```bash
npm install
npm run dev
```

提交前：

```bash
npm run build
```

`npm run build` 会先校验 Markdown JSON、项目编号和跨页面关联，然后生成网站。推送到 `main` 后，[GitHub Pages 工作流](.github/workflows/deploy-pages.yml)负责发布。

## 公开信息与隐私边界

本仓库以及生成的网站都按公开材料管理：

- 可以提交：公开学术邮箱、公开教育与工作经历、公开论文、专利、数据集、脱敏项目名称和公开合作关系。
- 不得提交：密码、令牌、API Key、私钥、身份证或护照信息、家庭住址、私人电话、未公开客户、合同与报价、内部项目资料、论文保密数据和 AI 私有交接记录。
- `.gitignore` 只能阻止新的未跟踪文件被加入，不能保护已经提交的文件。
- 删除当前文件不会自动清除 Git 历史；发现敏感信息时应立即停止发布，并按敏感数据清理流程处理历史记录。
- `package.json` 中的 `"private": true` 只用于阻止误发布到 npm，不代表 GitHub 仓库是私有的。

需要保密的 AI 工作记录、原始材料和未公开内容统一保存在私人 Notion 主库中。公开仓库里的单个 README 或 Markdown 文件不能单独设置为私密。
